# 群设计画布(飞书画板)

[English](../BOARD.md) · 简体中文

> 群成员和 agent 共用一块**飞书画板**做生图呈现与标注迭代:agent 把图、图表放上画板,群成员在画板上画箭头、贴便签、写评论,回群里说一声,agent 就按标注改图(开了[自动感知](#自动感知轮询)时不用说,群里自动出一张反馈卡,点一下即可)。画板由飞书云托管,桌面和手机都能原生打开;SintBot 只出站调 API,不自托管页面、不需要公网入口。仅飞书可用。
> 实现:`src/platform/board.js`(纯函数)· `boardwatch.js`(自动感知)· `boardnotice.js`(卡片回填)· `boardops.js`(自编辑留痕)· `bin/sbot.js` 的 `sbot feishu board-*`。

## 怎么用(群成员视角)

- **不用知道「画布」这个概念**:群里说「画一张…」「出个流程图」,agent 第一次需要展示图像时自动建画布、把链接发进群,并挂在群顶部的标签页上。
- **群 = 通知流,画布 = 工作区**:少量图同时发群;批量(三张以上)只发画布链接,免得刷屏。每张图下有标签节点(「方案1」「v2 · 按标注修改」),群聊里好指代。
- **标注迭代**:在画板上画箭头 / 贴便签 / 写字 / 写评论 → 回群里说「按标注改」→ agent 现拉标注与评论,改图后新版放在原图右侧同排。
- **开了自动感知时**:不用回群里说。群里会自动出一张「画布有新反馈」卡(标注与评论合成一张,列出数量和预览图)→ 点「按标注改图」→ 结果回填到同一张卡里。
- **直接改了画布**(改了图表上的字、删了节点):agent 只把改动并回源文件,不重新渲染、不另出新版。开着自动感知时,这种改动出的是「画布内容已修改 · 同步到源码」卡。
- **画布 = 设计演变档案**:历史版本图和标注都保留,「原图 → 标注 → 新图」的链条一眼可见;评论处理完标记为已解决。只有群里明确要求清理时才删,删掉的节点存档到项目的 `design/board-history.jsonl`。
- 卡上的「忽略」按钮把卡翻成灰色「已忽略」,防止以后误点旧卡触发一轮。

## 核心机制:按标注改图

- **标注工具就是画板原生的**:箭头(`connector`)、便签(`sticky_note`)、文字(`text_shape`)、笔迹(`paint`),手机上也能画。
- **读回是结构化的**:`GET nodes` 返回带坐标的 JSON,箭头带着吸附的目标节点 id ⇒「这条标注针对哪张图」没有歧义。
- **喂给模型的是干净原图 + 结构化标注清单**,而不是「把箭头烤进去的截图」。所以**不能识图的文本模型群(`vision:false`)也能按标注改**:纯坐标与文字就能驱动。边界:「需要看见才懂的『这个改成那样』」仍要能识图的模型。
- 点「按标注改图」时,合成消息自带**本轮播报的标注清单** ⇒ agent 只处理这一轮的标注,历史标注保留也不会被误处理。

## agent 用的子命令(`sbot feishu board-*`)

| 子命令 | 作用 |
|---|---|
| `board-create [--title] [--new]` | 建画布文档 + 画板,分享给本群(可编辑),放一张「使用说明」便签,挂群标签页;已有就给链接 |
| `board-add-image <图> [--beside <节点id>] [--x --y --width --height] [--label] [--deliver]` | 上传图片节点。`--beside` = 放在参照图右侧同排(按标注改图必用,多版自动避让);缺省放在全板最右侧。`--deliver` 把结果回填到触发它的那张反馈卡 |
| `board-add-diagram <源码> [--type] [--syntax mermaid\|plantuml] [--as-image] [--beside] [--label] [--deliver]` | Mermaid / PlantUML 源码 → 可编辑的图表节点,见下 |
| `board-add-nodes <节点JSON>` | 直接写结构化节点(Mermaid 表达不了的自由布局 / 思维导图 / 分区),最多 3000 个 |
| `board-nodes [--raw]` | 读节点摘要:图片 / 箭头(含吸附目标)/ 文字 / 图形 / 思维导图 / 组 —— **读标注用它,不靠截图** |
| `board-del-node <id…> [--no-cascade]` | 删节点,默认连带组成员与思维导图子树;**一次传完所有 id** |
| `board-comments` · `board-resolve-comment <id>` · `board-get-media <token> <路径>` | 读评论 / 标记已解决 / 下载评论附图与画板素材 |

- 在 `Bash(sbot feishu *)` 基础技能白名单里,任何权限档都能用(codex 群照例要完全访问档)。
- 画布状态存在配置的 `groups[<chatId>].board`(加锁写,daemon 热重载)⇒ agent 的自知清单在有画布时自动多出【设计画布】一段:链接、子命令用法、约定(读标注用节点数据不截图、新图放右侧不动原件、`vision:false` 群「画板上的图你看不见,以节点数据为准」)。
- 文字、标题、标签过出站脱敏;图片路径走项目目录围栏。

## 图表通道(Mermaid / PlantUML)

agent 写 Mermaid(优先)或 PlantUML 源码,存在 `design/diagrams/*.mmd` 进仓库,一条命令变成画板上**可编辑、可标注、可删除**的节点。用途:产品功能先出流程图评审、技术方案先出架构图评审,评审过了再写码 / 生图 —— 图便宜,返工贵。

- 飞书的渲染端点不能指定位置、生成的容器子节点也删不掉 ⇒ SintBot 先在每群一块**群里看不见的暂存画板**上渲染,读回节点、净化、平移到主画板的空白处,再一次性写进主画板。写进去的是普通节点,所以位置可控、可删、标注箭头能吸附。整张图表会编成一个组,整体拖动;组内图形仍可单独改字、单独删。
- 降级:可编辑移植失败 ⇒ 整图作为一张图片上板(裁掉留白,PNG 同时存进 `design/diagrams/`)⇒ 再不行才直接渲染到主画板并提醒可能重叠。`--as-image` 直接走整图(好拖、不可编辑,只适合一次性示意图)。
- Mermaid 的多行标签要写 `<br/>`(`\n` 会原样显示成两个字符);子图容器不吃 `classDef`,要用 `style <子图id> fill:…,stroke:…`。

## 自动感知(轮询)

- **默认关**。`feishu.board.pollSec` 设成正数才开(建议 120,最小 30),改了要重启 daemon。
- 开着时,daemon 对**建过画布的群**每 `pollSec` 秒拉一次节点与未解决评论,和基线比对出:新增节点、改了文字的节点、删掉的节点、新评论。纯挪动 / 缩放 / 改样式不算(视作整理)。
- **等人停笔再播**:画板没有「谁在编辑」的接口,只能看变化有没有停 —— 发现变化先押后,到下一轮整板指纹不再变才播累计的变化;连续编辑最多押 `holdRounds` 轮(默认 5,约 10 分钟)。新评论不等,立即播。
- **自己的动作不播**:agent 的写动作(放图、建图表、删节点)把服务端返回的节点 id 留痕在 `~/.sbot/board-ops/`,轮询前先并进基线 ⇒ 机器人放图不会自问自答,同一时间用户画的标注照样只播用户的。
- 播报只是群里一张卡,**零模型调用**;要不要起一轮(花额度)由人点按钮决定。
- **调用量**:每个有画布的群每轮约 2 个飞书 API 调用,120 秒一轮 ≈ 每群每月 4 万次。飞书 API 有租户级月调用量上限,所以默认关。
- **关着时**:画布标注不自动播报,群里说一声 agent 就现拉;agent 的自知清单也会写明「不会自动播报」,它不会对群成员说「你改完我会自动收到」。
- 飞书的 `board.whiteboard.updated_v1` 事件在正确配置下也没投递到长连接(只有它不来,`im.*` 事件都正常),所以主触发是轮询;事件路径保留,哪天投递正常了两路共用基线,不会重复播。

## 开通(飞书开放平台)

除 [platforms/feishu.md](./platforms/feishu.md) 的基础权限外,画布还要这 12 个 scope(都开**应用身份**那一档),开完要发版:

`docx:document:create` · `docx:document:write_only` · `docs:document.media:upload` · `board:whiteboard:node:read` · `board:whiteboard:node:create` · `board:whiteboard:node:delete` · `docs:permission.member:create` · `drive:drive.metadata:readonly` · `im:chat.tabs:write_only` · `docs:document.comment:read` · `docs:document.comment:update` · `docs:document.media:download`

- 反馈卡上的按钮要在「事件与回调 → **回调配置**」订阅「卡片回传交互 `card.action.trigger`」,选长连接(和事件订阅是两条独立通道)。
- 「明明开了权限还被拒」先查两条:①同一个 scope 分「用户身份 / 应用身份」两个开关,SintBot 用的是应用身份;②发版后飞书缓存的旧 token 到期前仍带旧权限集(最长约 2 小时)。
- 控制台「设置 → 飞书应用」卡里有完整清单与一键预检。

## 配置

```jsonc
"feishu": {
  "board": { "pollSec": 0, "holdRounds": 5 }   // 自动感知:0 = 关(默认),要开填 120(最小 30)/ 最多押后几轮;改了要重启 daemon 才生效
}
```

## 平台事实(实测,写代码时要知道)

- **没有删除端点**:删 = 读全量再 `overwrite` 重写 ⇒ 每删一次**整板节点 id 全变**,后续操作要重读;画板不能删空(至少留一个节点);读写之间用户的并发编辑会被覆盖(秒级窗口)。
- 写节点时服务端会改写传入的 id(`n1` → `d1:1`),以响应为准;同一批里的节点可以互相引用(箭头吸附、组成员),服务端会同步改写。
- **只读字段被静默丢弃**:比如给 `group` 写 `children` 不报错、照常返回 id,但组关系不生效 —— 正确做法是成员写 `parent_id`,组的位置尺寸要显式给。「POST 成功 + 返回 id」不等于生效。
- 整板导出(`download_as_image`)固定 2560×2560 JPEG、内容等比缩放居中,规则未公开;近期导出过的板再导出会返回旧快照。卡片预览靠「导出 + 裁掉白边」,不靠坐标映射。
- 图片素材上传用 `parent_type=whiteboard`:实测可用,但官方文档的枚举里没有这个值,属未文档化行为。
- 空画板的读节点响应里没有 `nodes` 键;写后短时间会报 `4003101 doc is applying`,要退避重试。
- 评论锚不到画板里的具体元素(只有「[画板]」字样),空间定位靠画箭头。

## 限制与明确不做

- 画板没有 html / embed / iframe 类节点,**不能把 AI 生成的 HTML 当活网页放上去**;只能截图成图片(只看不可编辑)。
- 画板上用户自己贴的图,agent 要用 `board-get-media` 下载后才看得到;`vision:false` 群看不到图片内容。
- 生图能力取决于模型:codex 群自带;其他群借本机 codex 订阅走 `sbot imagen`。
- 机器人建的文档在应用空间里;文档被删或移走时,子命令会说「画布文档不存在或无权访问,可重建」,agent 重建前要先问群里。
- 不做:画板上的「生成中」占位节点、新增斜杠命令(自然语言触发即可)。
