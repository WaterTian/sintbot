## 群项目基础能力

每个群的 agent 每轮都收到一份**自知清单**:身份、项目目录与仓库状态、模型与执行权限、控制台地址、本群已启用的插件,以及下面这些能力怎么用;能力或配置变了下轮自动重注入,**不重置会话**。清单里的命令名是给 agent 执行的,它对群成员说话按「零工具名」约定只说人话。基础技能白名单(`Bash(sbot feishu|wecom|cron|imagen|design|preview *)`)在任何权限档都放行;codex 群的只读沙箱无法联网,这些要完全访问档才可用。

- **飞书基础技能** `sbot feishu` —— 发文件 / 图片 / 消息,拉群历史(每条带 `message_id`,并标 `→@某某·未@bot` / `→@bot`),回复 / 编辑 / 撤回 bot 自己的消息,下载群附件,表情回应。路径围在项目目录内,出站文本过脱敏(密钥恒遮;手机号/邮箱按群 `redactPii` 可关)。
- **设计画布(飞书画板)** —— 群里说「画一张…」时 agent 自动建板并发链接;图与图表上板、群成员在板上画箭头 / 贴便签 / 写评论,回群里说一声 agent 就按标注改图。**图表通道**:agent 写 Mermaid / PlantUML 源码(`design/diagrams/*.mmd` 进仓库)即成可编辑、可标注、可删除的节点。**自动感知**默认关:设 `feishu.board.pollSec: 120` 打开后,建过画布的群每 120 秒拉一次(每次约 2 个调用),有新标注群里自动出「画布有新反馈」卡,点按钮即改、结果回填同一张卡;飞书 API 月调用量是租户级硬约束,开之前先算额度。全部机制与真机事实见 [docs/BOARD.md](../BOARD.md)。
- **设计风格档** `sbot design` —— 项目根 `DESIGN.md`(或多份 `design/styles/<用途>.md`,front matter 的 `platform:` 说明管小程序还是后台)= 色板 / 字体(拉丁族 + 中文档位)/ 圆角 / 状态色 / 渐变 / 投影 / 图标 tokens + Do's / Don'ts;16 种内置预设,控制台可自建、复制、从参考网址或本机目录提炼、把项目档收录进全局库;tokens 每轮直接进清单(不是给路径)。**四条平级验收**:`check`(页面写法对照档:色板 / 圆角 / 字体 / 字体可得性 / 图标参数与来源)· `doctor`(档本身:语义色放错段 / 对比度 / 非标准字重 / 中文兜底 / 首选字体是否系统自带)· `layout`(渲染出来的几何:文字重叠 / 裁切 / 点击目标 <24px / 中文小字 / 对比度,须常驻 Chrome,多档宽度)· `icon-assets`(图标文件:颜色能否继承 / 同图多份 / 参数偏离)。**只报告不阻断**:有偏离退出码 3(≠ 命令失败),判定合理的记进 `design/check-accepted.md`。多份档时每条命令要指名:`--as <用途>`(生图是 `--style`),不指名用第一份并会说明。
- **图标体系** —— 设计系统的第四维(前三 = 色板 / 字体 / 圆角)。项目图标档 `design/icons.md` 选系统:Lucide / Tabler(描边型,互为兜底)/ Phosphor / Pixelarticons(填充型);`sbot design icon <名字…>` 按语义名取图标,按风格档归一描边 / 尺寸并自带无障碍名,`--sprite` 出雪碧图;取出的图标带来源指纹,`check` 能查出页面里混进别家的或换系统后没重取的。四个图标包约 160MB **不随包分发**,机器上单独装,没装只降级。契约见 [docs/ICONS.md](../ICONS.md)。
- **生图桥** `sbot imagen` —— 任何模型的群都能借本机 codex 订阅生图,零 API key。受理即返回、detached worker 完成后发群(群里有一张会自己更新的进度卡);`--wait [秒]` 原地等:0 完成 / 1 失败 / **2 仍在跑,不是失败**。`--ref <图>` 编辑(在这张图上动手,不是照描述重画)· `--mask` 只重绘遮罩透明处 · `--transparent` 真透明底。同一输出路径重投会被挡(退出码 2),失败留下的半成品挪到 `.partial`、正式路径保持不存在;属于设计流程的图自动上板,散图加 `--no-board`。可选装 rembg 做保真抠图。
- **群预览服务** `sbot preview start <目录或文件>` —— 给群成员看 HTML 原型的**受管**方式:detached 静态服务、端口段 4610–4629 按群固定、URL 带 token 前缀、默认只服务项目子目录(项目根须显式 `--project-root` 并会告知群)、闲置 / 超龄 / 群暂停 / 解绑自动回收并通知群,控制台概览可见可停。agent 不必再自己起常驻服务或拖着轮次不结束。见 [docs/PREVIEW.md](../PREVIEW.md)。
- **定时任务** `sbot cron` / 控制台群卡 —— `--do "<指令>"` 到点构造一条合成消息起一轮 agent(走全套群管线),`--say "<文本>"` 到点只发一句不起 agent,`--run "<命令>"` 到点在项目根直接跑命令不起 agent、不占群锁(退出码 0 只留日志与账本一行;失败群里一句提示附输出末尾,`--escalate` 改为交给 agent 排查;`--timeout <分钟>` 默认 15;`--say` 正文与失败提示**发不出去时按 1/5/15/30 分钟补发**并注明原定时间,四次不成才放弃)—— 「脚本自己发报告、agent 只确认退出码」的巡检 / 日报一律用它;时间支持标准 cron、`每天 09:00` / `工作日 8:30` 中文简写、`--at "YYYY-MM-DD HH:mm"` 一次性(触发后自删),全部按产品时区。⚠ `--do` 任务是群锁的隐形竞争者,高频要当持续成本审。
- **群内反馈本** `/issue <一句话>` —— 群成员自己报问题(不限管理员),落本机 `~/.sbot/issues.jsonl` 事件流,**自动附上一轮技术指纹**(状态 / 耗时 / token / 模型 / 失败原因);控制台概览「反馈本」可一键标记并回原群告知,`sbot issue list --json` 供跨机汇总。每台机器一本、各自发号,与代码托管平台的 issue 无关。
- **跨模型记忆交接** —— 群内 `/model` 换脑后不丢项目积累:清单点名项目根存在的 `CLAUDE.md` / `AGENTS.md`(两份都点,claude 与 codex 各只自动读一份)与长期记忆目录的位置和条数**档位**,并钉死单一落点;只给坐标不搬内容。claude 非完全访问的群不指记忆目录(它够不着,指了反而教出「这项目没有记忆」)。

## 控制台

内置一个**本地网页控制台**(daemon 自带,Node `http` + SSE,默认只绑 `127.0.0.1`,自包含单文件前端):

```bash
sbot ui           # 配置模式:配置 / 健康 / provider 测试 / 群绑定(不接 daemon)
sbot start --ui   # daemon + 控制台:额外有实时活动、配置热重载、按群实时切模型
```

默认 `http://127.0.0.1:4600`(`--ui-port` 换端口,`--no-open` 不自动开浏览器)。四个页签 + 试跑:

- **概览** —— 健康(有无可用模型/群,MCP 可达)· 并发仪表 · 每群忙闲 · **每群运行控制**(■ 停止 / ↺ 新会话 / 向群里插一句,daemon 共宿时;新会话在忙时=中断当前任务+清队列+开新)· 实时活动流(turn 流式 / tokens / 耗时,可展开看完整内容)· **反馈本**(待处理置顶、一键标记回群)· **预览服务**(运行中的可见可停)
- **模型 · 库** —— 三类**全局资源**:①管理 provider(➕ 添加〔预设/自定义〕· ⚙ 配置参数〔第三方 = 端点 / key / 思考深度;**Claude 走订阅登录专属面板,无端点/key 两栏**,登录态真探 + 模型下拉 + 默认跟随 CLI〕· 一键测试 · **余额 / 订阅额度**〔百分比 = **已用**,右侧「↻」可单刷一个 provider〕· 隐藏 · 拖动排序;未配置的自动不显示)②**插件库**:Claude(`~/.claude.json`)/ Codex(`~/.codex/config.toml`)两套 MCP 命令行安装、即时刷新(不参与拖排序)③**设计风格库**:内置 16 种预设 + 自建(表单 + 实时预览 / 从参考网址或目录提炼 / 复制为新款 / 原地修改)的预览图网格,供各群挑用 ④**图标库**:四套系统的真实样张与叫法,群卡上按项目选系统与线性 / 实心
- **群 · 项目** —— **纯配置**页:创建群项目(建群拉人 / 浏览选目录〔限项目根 `~/Projects`,Win `D:\Projects`;可在其下**新建项目文件夹**〕/ 解散群)· **按群切模型**(切换即重置该群会话,下条消息生效)· **按群执行模式**(「受限 ⇄ 完全访问」段控:Claude=白名单/dontAsk,codex=只读/read-only;第二段=bypassPermissions/danger-full-access)· **按项目工具权限**(三档预设 只读 / 开发 / 全信任 + allow/deny 手改,仅限本项目目录)· 插件按群勾选 · 定时任务 · 仓库地址(SSH,幂等 init + origin,连通性探测)· 设计风格行与图标系统 · 预览常驻 · 数据明文开关 · 暂停 / 恢复 · 解除绑定。运行控制(停止 / 新会话 / 插话)在「概览」
- **试跑** —— 网页版 `agent run` / `chat`,选 provider + workdir 流式对话
- **浏览器接管页**(独立页面 `<控制台地址>/browser`,导航栏里没有入口)—— **接管机器人的常驻浏览器**:画面推到这一页,手机或电脑上直接点、拖、输入(登录 / 验证码 / 滑块 / 扫码这类只有真人能做的一步);群成员凭 agent 在群里发的**一次性链接**(只能打开一次、默认 10 分钟)也能进这一页,进不了控制台其它地方。见 [docs/BROWSER.md](../BROWSER.md)「远程接管」
- **设置** —— 运行限制(并发上限 / 单轮超时;**执行权限按群设、无全局**)· **访问地址**(本机 / 局域网 / 公网 URL + 密码提示;登录态下有「退出登录 / 退出所有设备」)· **飞书应用卡**:可折叠**开通指引**(机器人能力 / 长连接订阅 / scope 清单 / **数据权限授权范围** / 发版)+ 一键**预检**(bot 身份·权限逐项 ✓✗,错误码→人话)+ **管理员多值**(`admins` 可多个:**从组织通讯录搜索选人** / 邮箱·手机号查 / 粘 openId,建群时勾选拉入)+ botOpenId + 响应范围。工具权限与按群执行模式在「群·项目」每张卡

配置改动在 `start --ui` 下热重载(运行中 daemon 下一轮生效)。

### 从局域网访问(手机 / 另一台电脑)

默认只绑 `127.0.0.1`(本机)。要从局域网其它设备打开控制台,**必须先设访问密码**,再对外绑定:

```bash
sbot ui --set-password        # 设置控制台访问密码(scrypt 存 config.ui.auth,永不明文)
sbot ui --host 0.0.0.0        # 对局域网开放(无密码会拒绝启动 · 启动时打印检测到的 LAN 网址)
# daemon 共宿:sbot start --ui --ui-host 0.0.0.0
```

- **有密码才对外**:`--host` 非环回时,未设密码直接 fail-closed 拒启动。设了密码后,LAN 访客的页面不再自动下发 token —— 需在登录页输密码,校验通过才拿到登录会话令牌(落盘 30 天)。
- **本机 loopback 永远免密**:即便对外暴露(`0.0.0.0`)并设了密码,**从本机 `http://127.0.0.1:4600` 打开控制台仍直接进、不弹密码** —— 密码只用来拦局域网访客,不该波及同机访问(判据是请求的 TCP 源地址是否 loopback,LAN 访客伪造不了)。**例外**:密码设在**纯环回绑定**(没 `--host` 对外)上时,视为「刻意给本机上锁」,本机也会提示登录。
- **只放行私网段**:对外时 Host 白名单放宽到 `10./192.168./172.16-31./169.254.`,DNS-rebinding(攻击者域名)仍被挡。
- **公网访问**不靠放宽白名单,靠一台有公网 IP 的服务器做入口:SSH 反向隧道 + nginx 终结 HTTPS;见 [docs/PUBLIC-ACCESS.md](../PUBLIC-ACCESS.md)。
- **公网上用飞书账号登录**:设置页填「公网地址」(https://域名)并把显示出来的回调地址加进飞书开放平台「安全设置 → 重定向 URL」,登录页就出现「用飞书登录」;**只放行「设置 → 飞书应用」里的管理员名单**。公网上密码登录接口由 nginx 直接 403,没有可猜的口令;登录会话记 30 天,守护进程重启不登出,设置页可「退出登录」。
- ⚠️ **HTTP 明文**:局域网内可被嗅探(密码/会话在传输中可见)。**仅在可信网络使用**;控制台是 operator 全权面(含在项目目录执行命令),等价一个开放的终端。要最稳,改用 **SSH 端口转发**:`ssh -L 4600:127.0.0.1:4600 你@主机`,再开本机 `http://127.0.0.1:4600` —— 零暴露、全程加密。
- 登录失败会 audit 到 `~/.sbot/audit.jsonl`(`ui-login`);移除密码 = 删掉 config 里的 `ui.auth`。

**访问 / 免密矩阵**(谁需要输密码):

| 绑定 host | 是否设密码 | 本机 `127.0.0.1` | 局域网访客 |
|---|---|---|---|
| 环回(默认) | 无 | ✅ 免密直进 | 🚫 打不开(未对外) |
| 环回(默认) | 有 | 🔒 需登录(刻意本机上锁) | 🚫 打不开 |
| `0.0.0.0` / LAN IP | 有(**必需**) | ✅ **免密直进** | 🔒 需登录 |
| `0.0.0.0` / LAN IP | 无 | ⛔ fail-closed 拒启动 | ⛔ 拒启动 |

## 浏览器自动化(可选)

要让群里的 bot 操作浏览器(且用**登录态**的真实站点),推荐 **常驻 Chrome + chrome-devtools MCP**:一个由 launchd/服务保活的 Chrome 实例(独立 profile、CDP 端口只绑本机),每轮 spawn 的 MCP 用 `--browserUrl` 连上同一实例 —— **登录一次永续、每轮免冷启动、codex/claude 两侧同源**,sbot 代码零改动 。

**为什么不让 MCP 每轮自己拉浏览器**:登录态要跨轮跨重启留存,而 Chrome 136+ 已禁止 CDP 挂默认 profile —— 独立持久 profile 是硬要求;常驻实例还能把反节流开关写进启动参数(`--browserUrl` 连现成实例时 MCP 不会替你附带),否则窗口被挡 / 显示器休眠时长任务会被节流卡死。

**完整配方见 [docs/BROWSER.md](../BROWSER.md)** —— 保活配置、MCP 两侧同一套 args(截图 JPEG + 限宽省上下文、`--allowUnrestrictedPaths` 让截图能落进项目目录再发群)、超时对齐(codex `tool_timeout_sec` / claude `MCP_TOOL_TIMEOUT`)、首登与掉登录 runbook、长页面整页截图、保养与故障速查。

**怎么装**:控制台「**模型 · 库 → 插件库**」有个**命令行添加框** —— 粘**完整安装命令**点「添加」(不是只打插件名;一次一条,`--scope user` 写入用户级 MCP 配置、与目录无关,成功后库列表自动刷新;建议**钉版全局安装**而非 `npx @latest`,免每轮过代理查 registry)。再去「群·项目」卡「插件」区**勾选启用**(安装是全局动作归库页,群卡只做按群门控;勾选即放行 `mcp__chrome-devtools__*`)—— codex 群则须把权限设成完全访问档。

> **没有常驻浏览器的机器**(只做一次性抓取,或没有图形登录会话)也可以让 MCP 每轮自启浏览器:`chrome-devtools-mcp` 不给 `--browserUrl` 时会自己拉 Chrome,`@playwright/mcp` 配 `--user-data-dir <持久profile路径>` 同理。代价是冷启动开销、登录态维护和反节流参数都得自己另想办法。
>
> Windows 上命令行添加框的**中文报错**已转 UTF-8(不再乱码);若仍见乱码,升级到最新版。
