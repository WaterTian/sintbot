# `sbot preview` — 群预览服务

[English](../PREVIEW.md) · 简体中文

> 群里让 agent 做了个 HTML 原型,群成员想**在手机上打开看看**。这件事做成一个**受管的确定性动作**:端口按群固定、目录围栏、带口令的链接、跨轮存活、闲置自动回收、控制台可见可停。agent 不必拖着轮次不结束给链接续命,也不必碰任何系统自启机制。
> 实现:`src/preview.js`(纯函数)· `bin/sbot.js`(三个动作 + worker + daemon 里的回收器)。

## 为什么要专门做

不受管时,agent 会用各种办法让链接活着:自己起静态服务、装成系统常驻作业(随后被忘掉,整个项目目录长期暴露在局域网上)、或者干脆**拖着本轮不结束**(占住群锁,群里后续每条消息都被顶成「已排队」)。光在提示词里写禁令不够 —— 禁令必须配一条正路。本技能就是那条正路,并替 agent 记着关。

## 形态:worker 持有端口,daemon 持有生命周期

- **HTTP 服务在 detached worker 里**(与 `sbot imagen` 同款)。daemon 是全群单点,不让一个吃局域网请求的 handler 进它的进程;daemon 重启(含升级)也不打断预览。
- **生命周期策略在 daemon**:记账、闲置回收、孤儿清理、群暂停联动、控制台展示。
- **worker 自己也会到点自尽** ⇒ 不装 daemon、只跑 `sintbot ui`、daemon 崩了,回收照样成立。两道保险,任一独立有效。

```
群 agent ──Bash──► sbot preview start design/prototype/index.html
                      │ 受理:围栏裁决 + 写记录 + detached spawn ⇒ 回读实际端口后返回 URL(不占群锁)
                      ▼
              ~/.sbot/preview/<id>.json ◄──── worker 心跳(lastReqAt / pid / port)
                      │                              │
       daemon 回收器(60 秒一轮)                    worker(node http,自带闲置自尽)
       闲置 / 超龄 / 群暂停 ⇒ 停 + 群通知             只服务围栏内的静态文件
       孤儿记录(pid 已死)⇒ 清理                     GET /<token>/… → serveRoot/…
                      │
              控制台概览「预览服务」区(端口 / 最后访问 / 剩余闲置 + 停止)· sintbot doctor 如实列
```

## 命令

```
sbot preview start <相对路径> [--label "记账原型"] [--port <n>] [--idle-min <n>] [--project-root]
sbot preview stop [<id>|--all]
sbot preview status [--json]
```

- `start` 收**文件**(自包含 HTML,主用法:**只服务这一个文件**)或**目录**(带 assets 的原型:serveRoot = 该目录,入口 `index.html`,缺了就拒,不做目录列表)。
- **受理即返回**:输出里给 URL,并明写「不要等待、不要轮询、更不要为了让链接有效而拖着本轮不结束」。绑定在本机环回时改说「局域网里的群成员打不开」,并给出 `send-file` 发文件的替代。
- **一群最多一个预览**:同一 serveRoot 再 start ⇒ 原样返回原 URL;换了 serveRoot ⇒ 停旧起新,并说明「已替换上一个预览」。整段「查 → 停旧 → 落新记录」按群加文件锁,并发 start 也只会有一个活着。
- `stop` 无参 = 停本群的。**在群里**(有群上下文)时:`--all` 直接拒,按 id 停也必须是本群的,`status` 只列本群;`--all` 只留给终端里的管理员。
- **在群里禁止 `--config`**:否则 agent 可以自己写一份配置把回收全关掉。管理员要换配置用 `SBOT_CONFIG` 环境变量。

## 端口

- 段 **4610–4629**(20 个),紧挨控制台的 4600,防火墙放行一次即可;避开 3000 / 5173 / 8000 / 8080 / 9222。
- 起点由群 id 哈希决定 ⇒ **同一个群恒用同一个端口**(没冲突时);被占就在段内环形顺延。worker 按候选顺序试绑并把实际端口写回记录,受理侧回读后才打印 URL ⇒ 打印出来的链接一定是活的。
- `--port` 可以指定,但必须在段内。

## 目录围栏

1. **相对路径 + 项目目录围栏**:拒绝绝对路径、`..`、越出项目目录。
2. **realpath 二次判定**:受理时 serveRoot 的真实路径必须仍在项目目录内;**每个请求**解析后的路径也再判一次(软链指出去 ⇒ 拒)。
3. **默认拒绝项目根**:serveRoot 就是项目目录时报错,让 agent 把原型放进子目录(如 `design/prototype/`)。确要如此须显式 `--project-root`,并在群里发一行告知。
4. **黑名单**(受理与每个请求两侧都查,不分大小写):点开头的文件 / 目录(`.git`、`.env`、`.ssh`…)、`node_modules`、`*.pem|key|p12|keystore`、`sbot.config*.json`。受理时查**从项目根到 serveRoot 的整串**,防止从点目录里挂出整棵子树。
5. **只读**:只有 `GET` / `HEAD`,其余 405;没有目录列表、上传、写。

**worker 也复核**:`sbot preview *` 在任何权限档都放行,所以 worker 不能信任它读到的记录 —— 记录文件必须在 `~/.sbot/preview/` 内,并以**配置里该群的项目目录**为锚点重跑一遍围栏(不信记录里自称的目录)。否则伪造一份记录就能把任意目录挂上局域网。

## 带口令的链接

URL 形如 `http://192.168.1.75:4612/<token>/index.html`,`token` 是随机的 10 位十六进制。

- 局域网扫描器扫到端口也拿不到内容(前缀不对一律 404),而群里的链接**点开就用**,不用登录。
- token 放在路径前缀而不是 query 里,HTML 里的**相对**资源引用照常工作;以 `/` 开头的绝对引用会失效 —— 所以首选自包含单文件。
- 默认监听 `0.0.0.0`(否则群成员打不开);`preview.host` 设成 `127.0.0.1` 可以只留本机。HTTP 是明文,只在可信内网用。

## 回收

| 触发 | 默认 | 谁执行 |
|---|---|---|
| 闲置无请求 | **30 分钟** | worker 自尽 · daemon 回收器兜底 |
| 起服务总时长 | **8 小时** | 同上 |
| 群暂停 / 解绑 / 解散 | 立即 | daemon 回收器 |
| `stop` / 控制台按钮 | 立即 | 当场 |
| daemon 关停(含升级) | **不动** | —— 预览是跨轮的东西 |

- **自动停止一定发一行群通知**(「预览已停止 … 还要看就在群里说一声」),否则群成员点链接打不开、会以为机器人坏了。例外:群暂停引起的回收不发(暂停 = 群里安静),暂停期间待发的通知直接丢掉、不攒着。
- 四个停止点(回收器 / 替换 / CLI / 控制台)都是**先把判定写进记录再杀进程**;worker 每次写记录前先回读磁盘,已被判停就不写并退出 —— 防止正在处理的请求把记录写回「运行中」、吞掉停止通知。
- 回收策略**每轮现读配置**:控制台改了某群的设置(比如勾上「常驻」),对正在跑的预览也立刻生效;写坏的值退回启动时的快照,不会被当成 0(0 的含义是「永不回收」)。
- 已知天花板:静态页加载完就不再发请求 ⇒ 有人盯着页面看 40 分钟,闲置计时照样到点(页面本身不受影响,只是点内链会断)。不往用户的 HTML 里注入心跳。

## 配置

顶层 `preview`(全部可省):

```jsonc
"preview": { "idleMin": 30, "maxHours": 8, "portFrom": 4610, "portTo": 4629, "host": "0.0.0.0" }
```

- `idleMin: 0` = 不按闲置回收(仍受 `maxHours` 管);`maxHours: 0` = 不限总时长;两个都是 0 = 常驻,`status` / doctor 会标出来。
- **按群覆盖**:`groups[<chatId>].preview` 可以覆盖上面任一项。控制台群卡上的「预览:常驻(不自动停)」勾选就是写这里(`idleMin: 0` + `maxHours: 0`),要二次确认,并在群里说一声。「要不要长期把一个目录暴露在局域网上」是管理员的决定,不该被群里一句话说服。

## agent 怎么被教

自知清单里只留一条正路:**需要局域网在线访问时用 `sbot preview start`**(自包含 HTML 仍首选 `send-file` 直接发群);原型放子目录;不要自己起长活服务、不要装成任何系统常驻 / 自启作业、**严禁靠拖着本轮不结束续命**。清单里不写具体端口和分钟数(会顺延、可配置,写进去可能是假话)。实际措辞以 `src/core/engine.js` 为准,关键句有单测钉住。

⚠ 这是清单软约束,不是权限层的强制:完全访问档的 agent 照样绕得开。真正的防线是:正路存在、控制台看得见、清单写明白。

## 控制台与 doctor

- 控制台概览的「预览服务」区:标签 / 群 / 端口 / 目录 / 起始 / 最后访问 / 剩余闲置 + 停止按钮。
- `sintbot doctor` 列出运行中的预览;服务项目根的、常驻的会单独标出。

## 明确不做

- **`--cmd "npm run dev"` 起任意进程**:那只是把「agent 自己起服务」换了个壳,回收、端口、暴露面全不可控。
- **HTTPS / 公网穿透 / 反代**:公网暴露是完全不同量级的安全命题。
- **登录鉴权**:点开就看是这个功能的意义;带口令的链接已经挡住了扫描。
- **目录列表 / 上传 / 任意写**,以及**一群多个预览**。

## 已知约束

- serveRoot 里的软链即使指向项目目录内的别处也会 404(判定是「必须在 serveRoot 内」):共享资源请放进原型目录。
- 控制台的预览列表不随实时事件刷新,预览自动停了要等下次刷新才消失;点一个已消失预览的停止按钮会提示「可能刚被回收」。
- daemon 停机期间死掉的预览,要等 daemon 下次启动的第一轮回收才在群里播报「意外停止」。
- 不支持 Range 请求:视频类原型拖不了进度条。
