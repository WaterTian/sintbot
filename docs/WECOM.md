# 企业微信接入(智能机器人 · 长连接)

> 第二个聊天平台适配器:`src/platform/wecom.js`。engine 只多读平台的三个自描述字段(`skillCmd` / `features` / `chatLabel`,见 src/core/interfaces.js);与飞书**可同时接**(路由器 `src/platform/multi.js`,群级 `platform` 字段分流)。
> 本文只写**接入事实与边界**(与飞书同时在线的形态逐项实测过)。

## 一、开通(不认证、免公网)

1. **注册企业**免费、不要营业执照:企业名称 / 行业 / 规模 + 管理员实名微信扫码。未认证 200 人上限,内部群 / 智能机器人都能用;认证(300 元/年)只影响对外功能,**不需要**。
2. **建机器人**:电脑端客户端「工作台 → 智能机器人 → 创建机器人 → 手动创建 → API 模式」(手机端不能建;管理后台「安全与管理 → 管理工具 → 智能机器人」同入口)。填名称 / 简介 / 可见范围;**使用方式选「多人使用」**;API 配置页选**「使用长连接」**,记下 Bot ID 与 Secret。保存时会弹一次使用规则确认。
3. **权限管理**(同页「权限管理」tab):「机器人创建权限」与「API 模式管理 → 可配置长连接的成员」默认全公司,不用动。
4. **App 里找它**:通讯录成员列表里没有 —— 顶部搜索名字,或「工作台 → 智能机器人」;群里从群菜单添加。⚠ 用微信侧「微信插件」登录企微的成员看不到智能机器人,要装企业微信 App 本体。
5. **官方命令行工具**(发送者姓名、群历史、助手发图发文件都靠它):`npm i -g @wecom/cli` → `wecom-cli auth init --manual` 填同一对 Bot ID / Secret。非交互环境要给它一个 TTY(expect),提示行是「请输入企业微信机器人 Bot ID」「◆  Secret」;凭据加密落 `~/.config/wecom/`。

## 二、配置(双平台并存)

**配了哪个平台就接哪个**:`feishu` 块(appId / appSecret)在就接飞书,`wecom` 块(botId / secret)在就接企业微信,两个都在就两个都接;每个群用 `platform` 说明属于哪边。旧的顶层 `platform` 字段已废弃(写了会被忽略,doctor 提一句)。

```jsonc
{
  "wecom": {
    "botId": "aib…",                         // API 配置页
    "secret": "env:WECOM_BOT_SECRET",        // 长连接 Secret;登记进按值脱敏
    "botName": "SintBot",                     // 剥正文里的「@SintBot」;不填只剥开头那一个 @
    "names": { "WangWu": "王五" },         // 手工映射(优先级最高);其次命令行工具搜人;都没有显示 userid
    "welcome": "",                           // 首次进入单聊的欢迎语;空 = 不回
    "cli": "wecom-cli",                       // 官方命令行工具可执行名;false = 不搜姓名、基础技能关闭
    "throttleMs": 800,                       // 流式帧节流窗
    "inboxDir": "~/.sbot/wecom-inbox",       // 入站图片 / 文件落盘处(默认)
    "pollSec": 0,                            // 「不 @ 也回复」:拉群历史的**平时**间隔秒;**默认 0 = 关**(平台设计就是 @ 才答;轮询碰官方使用规则、>10 人企业返回 853006);小测试群可填 20。按群分档:刚聊过 8s · 平时 pollSec · 10 分钟没人说话 max(6×pollSec, 120)s
    "followSec": 300,                        // 跟进窗口秒:被 @ / 回复后这么久内不 @ 的消息也喂模型;0 = 群里每句都喂(很烧额度)
    "keywords": ["机器人", "助手"],          // 点名词:正文含它或机器人名就喂(可省)
    "gatekeeper": { "provider": "deepseek", "model": "deepseek-v4-flash", "maxPerMin": 6 }
                                             // 第二道门(可省 = 没有):规则不放行的消息先问这个便宜模型要不要答(直接 HTTP 问一句 YES/NO,不起 CLI);
                                             // 只能指有 baseUrl+apiKey 的模型(订阅登录的 claude / codex 不行,doctor wecom.gate 行会说);也可写成字串 "deepseek";
                                             // model 可省(用该模型默认型号,建议填最便宜的);maxPerMin 每群每分钟最多问几次(默认 6)
  },
  "groups": {
    "wrXXXXXX…": { "workdir": "…", "platform": "wecom" },   // 群 chatid:控制台绑定时写入 platform;单聊的 chatId = 对方 userid
    "oc_…":      { "workdir": "…", "platform": "feishu" }
  }
}
```

**群没写 `platform` 时**按 chatId 形态推断(`oc_` 飞书 / `wr` 企微,两者不会撞);企微单聊 id 没有形态,只配了一个平台时归它,两个都配且认不出 ⇒ 不归任何一边、doctor 报 warn,运行时只认该会话最近一次入站用的适配器(消息从哪边来就往哪边回),没见过入站的合成消息不发、记日志。推断只写内存态,控制台重新保存该群时才落进文件;显式 `platform` 与 id 形态打架(`oc_` 标企微)控制台直接拒。

⚠ **配了就接**:同一个机器人只许一条长连接,**两台机的配置都填同一对 Bot ID / Secret 就会互踢**(新连踢旧连、60s 后再抢,循环)—— 每台各建各的机器人;启动横幅会点名接的是哪个机器人。

**运行时**:`src/platform/multi.js` 把各适配器包成一个 Platform —— 入站消息带着自己的适配器进引擎(自知清单按适配器分流),`send / sendCard / reply` 按 chatId 查群配置分发(定时任务 / 升级播报 / 运维告警 / 控制台群通知全走它),查不出归属且有多个平台就不发、记日志。飞书专属子系统(画布 / 接管卡实体更新 / 表情确认)只在配了飞书时装。

`sintbot doctor`:`feishu` / `wecom` 各按配置报(配齐 ok / 缺项 fail,都没配只 warn 一行)· `wecom.cli` 行(工具没装只 warn,降级 = 群里显示 userid、助手不能发图);⚠ 工具对「消息 / 通讯录」各有**独立的 7 天能力授权**,`auth show` 看不出 —— 预检单独探「通讯录授权」,运行时撞到 850003 进运维告警群(创建者点续期链接);853006 = >10 人企业官方未开放 chat.*,不是配置错· `platform` 行(顶层字段废弃)· `groups.platform` 行(推断了几个 / 哪些判不出)· 群行标成没配的平台 ⇒ warn「收不到消息」。

**控制台**:「设置」页「企业微信机器人」卡与「飞书应用」卡并列,两张卡默认收起、卡头一行摘要(凭据 · 预检〔凭据形状 / 工具装没装 / **工具授权的是不是同一个机器人** / 可绑定群数;只调本机命令行工具,不另开长连接〕· 身份与连接〔机器人名 / Bot ID / 长连接实时状态〕· 机器人名 / 欢迎语 / 成员显示名 · 不 @ 也回复〔间隔 / 跟进窗口 / 便宜模型门控 / 点名词〕· 命令行工具开关);「群·项目 → 配置群项目」两个平台都配了时第一步出平台切换,企微形态 = 指引 + 刷新 + 候选(**机器人被 @ 过的群**,官方 CLI 两路合并,群名顺手回写)+ 手填,保存写入 `platform`;群卡带平台徽标,企微群不渲染画布行;概览「飞书连接」「企业微信连接」各一行。企微没有建群 / 解散 / 拉人的接口 ⇒ 新群要在企业微信里建、把机器人加进群、@ 它一次,再回控制台选。

## 三、行为与边界(实测)

| 项 | 企微 | 适配器怎么做 |
|---|---|---|
| 收群消息 | **长连接只推 @ 机器人的消息** | 正文剥 @。**两车道**:@ 消息走长连接快车道 —— 群忙时插到队里所有轮询消息之前、出队不与轮询消息混批、全局并发给它留一个槽、答完 4s 补拉一次该群历史;不 @ 的消息走轮询慢车道 —— 排队不提示、同一轮放行的多条攒成一批一轮答完、推送回复开头引一行「回复 某某:原话」(推送不会自动引用,群里才分得清在回谁;攒批时注明「(连同前 N 条)」、多人时「某某 等 N 人」)。**「不 @ 也回复」**(**默认关**;开 = `pollSec` 填 20 左右):按群分档用官方工具拉已绑群的历史(零 token)—— 跟进窗口内 8s 一次 · 平时 `pollSec` · 10 分钟没人说话 max(6×pollSec, 120)s 一次;850003 / 853006 整体暂停 30 分钟再试并进告警群;新出现的人类消息过一道**规则门控**才喂模型 —— 点了机器人名 / 「机器人」「助手」的随时喂;被 @ 或机器人开口后 `followSec`(300)秒内的跟进也喂;其余只留历史不喂(每喂一条就是一轮、带整段会话,很烧额度;`followSec:0` = 全喂,`pollSec:0` = 关)。轮询来的消息没有 req_id ⇒ 回复走主动推送、没有流式;与长连接已投递的 @ 消息按**纯文字** + 3 分钟窗去重(只发一张图 @ 机器人时两边都是空串才对得上);启动第一轮只建基线不回放旧消息。**第二道门(可选,`gatekeeper`)**:规则不放行的消息,拿最近 8 句群聊 + 这一句问一个便宜模型「机器人该不该接」,YES 才喂(每条几十到一百多 token、不带会话、不起 CLI;宁漏不误 —— 问不通 / 看不懂 / 太短 / 限速一律当 NO;纯媒体没文字不问;控制台配上 / 换模型 / 关掉都热生效) |
| 收单聊 | 全部 | chatId = 对方 userid |
| 发送者 | 只有 userid(超管建的 bot 是明文;否则密文 woA2…,守护进程提醒一次) | 姓名:names 映射 > 缓存 > 工具搜人(首次见到等最多 5 秒;按 userid 搜是把名→ID 接口反着用,能中是巧合)。开着轮询时**从群历史桥接**:同一条消息两边都见到的那一刻把明文账号 ↔ `user_name` 记进缓存,零额外调用 |
| 图片 / 文件 | 链接 5 分钟失效、AES 加密;群里只能靠图文混排带图 | 到手即下载解密落盘(解不出按下载失败报),正文给 `[图片 path=…]` 标记;同一会话内串行保序、会话之间互不等待。**群历史里的图片 / 文件(轮询来的)**:门控放行后按 media_id 调工具取内容(回包两形态:框架落盘给路径 / 短内容内联),搬进收件目录按内容嗅探扩展名改名,正文同样给 `[图片 path=…]`;取不到给「[图片 下载失败]」让 agent 知道这里有张图没拿到(原因只进日志 —— 原话里有工具名 / 路径,agent 会复述) |
| 流式回复 | 同一 stream.id 全量替换;**首帧起 10 分钟内必须 finish**;单帧 ≤ 20480 字节 | 到龄或超长时把本段已发出的内容定格,另起新 stream.id 只续断点之后的文字(「接上条」);收尾文本不以定格文本开头(里程碑被剥)就整段重发;帧间节流 |
| 多次回复 | 同一 req_id 24h 内可多次回复 | 排队 / 进度 / 最终正文都走回复;合成消息(定时任务 / 控制台插话)走主动推送 |
| 主动推送 | 要该会话先有人给机器人发过消息;只认 markdown / 卡片 / 媒体 | 新群建好先 @ 一下;版本播报 / 告警 / `cron --say` 照常 |
| markdown | ≤ 20480 字节;不渲染表格、跨行代码块、HTML 标签(`<font>` 原样露出) | 表格改列表(表头加粗、≥4 列每格带表头名)· 代码块去围栏逐行包成行内代码 · 标题改加粗行 · 标签只留文字 · 页脚(耗时 / tokens)做成引用行;超长按行切片多条发 |
| 卡片 | button_interaction;按钮事件走长连接;更新须沿用原 task_id | `sendCard({title,desc,buttons})`;事件进 `hooks.onCardAction`,返回 `{card}` 即 5s 内更新 |
| 撤回 | 无事件 | 「撤回即停」不可用 |
| 断线 | 期间消息不补发;**TCP ESTABLISHED ≠ 订阅还活着** | 30s ping,75s 无回包主动掐线;看门狗退避重建;被另一条连接踢下线后让 60s 重连一次,**10 分钟内第二次被踢就停连并发运维告警**(官方口径:避免多连接;两台配同一 Bot ID 会每分钟互踢),重启守护进程才再连。**任一平台连接非 connected 持续 5 分钟 ⇒ 发运维告警群**(`alerts.chatId`,恢复再报一条;开机 DNS 未就绪那 2 分钟不会误报;断的若是告警群所在平台则发不出、只记日志) |
| 画布 / 表情 / 编辑撤回 | 无 | 自知清单按 `platform.features` 不教这些动作 |

## 三之二、已按平台分流的三条路

- **生图完成通知**:企微群 = 官方命令行工具发图 + markdown,没有进度消息(工具发的消息改不了);飞书群仍是卡片。清单照常教 `sbot imagen`。
- **接管浏览器入口**:`sbot browser link --send` 在企微群发「页面截图(有页面时)+ 带链接的 markdown」,没有按钮卡与三态翻卡,兑换 / 过期由接管页自己说。
- **发送者姓名**:首次见到某人等一次搜人(最多 5 秒)再投递,首条就显示姓名;手工 `names` 优先。⚠ 不能靠群历史预热:历史里的 `userid` 是工具那套 `woA2…`,与长连接的明文对不上。告警群是企微群时 doctor 提醒要先 @ 过机器人。
- ⚠ **工具的时间字面量按北京时间解释**(与主机时区无关;按主机时区格式化会把窗口错开、查成空),窗口取 6 天(整 7 天被拒)。

## 四、基础技能 `sbot wecom`

`send-msg "<文本>"` · `send-image <路径>` · `send-file <路径>` · `history [n]`(history 返回的是工具给的「人类发言」列表,实测不含机器人自己发的)。走官方命令行工具(以机器人身份、HTTP 直连)—— **不能**自己再开一条长连接,开了就把 daemon 踢下线。单聊 chat id 两套空间(长连接给明文 userid,工具只认它自己的 woA2… 形态),命令里不是 `wr` 开头的目标会先搜人换算。

## 五、已知限制与待验

- **「@所有人」不算 @ 机器人**:长连接不投递,机器人不会应 —— 群成员以为喊了全员机器人会答,其实不会,要在群里说清。
- 「不 @ 也回复」/ 便宜模型门控 / 群历史媒体下载 / 姓名桥接,这四件只在开着轮询(`pollSec` > 0)时工作。
- 门控只管跟进窗口**外**的消息;窗口内的闲聊仍按规则放行,由模型自己判断不回(代价是一轮)。纯图(没文字)在窗口外不喂,属设计。
- 官方没有任何「不 @ 也收」的开关 / 事件 / 参数;引用机器人的消息而不 @ 也不触发;会话列表的 `last_msg_time` 对不 @ 的消息不更新,不能拿来当探针;拿全量消息只有会话存档(要固定公网 IP + 按席位付费),不做。想连着聊,建议私聊机器人。
- 画布播报卡是飞书形状,企微群里不发。
- 单聊里的图片 / 文件解密只有单元测试,还没在真机上入站验证。
- 连接中断 / 被挤掉停连 / 工具授权过期三条运维告警:代码与单元测试就位,真机上还没触发过。
- 断电重启后偶见一条「另一条连接用同一个机器人登录」事件,而连接实际没断、ping 正常 —— 疑似服务端对旧连接的清理通知;之后 @ 消息是否照常收到待观察。
- 没做:定期检查已绑的群是否还在(`sessions list` 不返回已被移出的群,这是唯一的「被移出」信号)· 流式首帧用 `<think></think>` 占位代替空白 · 控制台企微卡显示「上次 850003 的时间」· `<@userid>` 能否在机器人 markdown 里 @ 到成员(待验)。
