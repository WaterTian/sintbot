# 图标体系 —— 契约

> 图标是与设计风格**平级**的一件事（图标库管「图形从哪来、叫什么名」，
> 设计风格管「怎么画它」，一个项目分别选 —— 详见下面「图标系统」一节）。本文是**共识本身**，不是使用说明：
> 目标、判据、明确不做、接口、代价，五格缺一格都不算谈拢。机制流水

## 1. 目标（做到什么算做到）

**让图标和色板一样，成为被声明、被携带、被验收的一等维度。**

要解决的不是"少一个检查器"，是**一致性没有载体**：风格档是唯一跨轮携带到 agent 眼前的东西，如果它不提图标，
色、字、间距、投影都定好了，图标却一片空白 —— 每做一个新页面，agent 就重新发明一套 path，一致性靠运气，
**而且丢了也没人知道**,直到有人肉眼看出来。

⚠ **一致性由「取得到正确图标」保证，不由「检查出不一致」保证。** 检查器只是兜底 —— 它能发现不一致，
造不出一致。这条决定了本方案的重心在 `sbot design icon`，不在 `design check`。

## 2. 判据（能区分两种实现的实验）

话可以各自理解，实验不行。以下每条都是**改之前必红**的用例：

| 实验 | 期望 | 它区分的是 |
|---|---|---|
| 风格档写 `strokeWidth: 2`，页面 CSS 里 `stroke-width: 1.8` | 报「描边不一致」 | 有没有真去读 CSS（真实案例就出在 CSS 而不是 svg 属性上） |
| 同一页混用 Lucide 与 Tabler | **不报** | 判据是「参数同构」还是「库名相同」 |
| `<img src="x.png" width="20">` | 报「栅格图当操作图标」 | 有没有按渲染尺寸设闸门 |
| `<img src="banner.png" width="750">` | **不报** | 同上（大图是插画/banner，不是图标） |
| svg 既无 `aria-hidden` 也无 `aria-label`/`<title>` | 报「缺无障碍名」**一条汇总**，不逐个点名 | 报告会不会变成噪音 |
| 风格档没有 `icons` 段 | 图标类零告警 + 一句「未启用图标体系」 | 有没有守住「没依据就不报」 |
| 取图标：主库没有的名字 | 自动落到兜底库 | 双库是不是真的接上了 |
| 取到的 Tabler 图标 | 占位框 `<path d="M0 0h24v24H0z">` 被剥掉 | 有没有做归一，而不是原样吐文件 |
| `<button>🔍</button>` | 报「emoji 当图标」 | —— |
| `<p>今天上新 ⚡ 很多 🎉</p>` | **不报** | **按位置判**还是按字符判（设计参照原型 1131 处 emoji，按字符 = 1131 条噪音） |
| `<button>开始答题 🎉</button>` | **不报** | emoji 与文字同段 ⇒ 是文案不是图标 |
| `<view bindtap="x"><text>🔥</text></view>` | 报 | 认不认小程序的点击绑定（只认 `onclick` 会漏掉整个小程序端） |
| 同页 24 网格的 `fill:none` 与 `fill:currentColor` 并存 | 报「线性实心混用」 | —— |
| 同页图标 + 200×200 带 fill 的插画 | **不报** | 混用判定有没有走尺寸闸门 |
| 图标档写 pixelart，页面里的 `home` 是 Tabler 的 path | 报「图标来源不符」 | **换系统后忘了重取**这件事有没有人管 |
| 同一张图、来源与当前系统一致 | **不报** | 判据是几何还是名字 |
| 名字在任何库里都没有（徽章 / logo） | **不报** | 会不会把项目自有图形当成"来路不明" |
| 当前系统的库没装，而页面里那张与别家几何不同 | **不报** | ③ 有没有偷懒改成"名字在别家有就算别家的" |
| 填充型系统的页面里有 `fill:none + stroke` 的图标 | 报「描边型图标」 | 选了填充型系统是不是反而查不出来源错 |
| sprite 顶部那行 `<!-- icons: … -->` 被删掉 | 报「图标署名不在这批文件里」 | 许可声明被"整理"掉有没有人管 |
| 单图标形态（从来不带署名）| **不报** | 会不会凭空指控 |

**误报预算**：拿一份真实产物（46KB、19 个内联 svg 的原型页）当基准，
**只许出 2 条**：描边 1.8 ≠ 2、18 个图标缺无障碍名。**多出来的每一条都是误报，都要回去改判据。**

**加了来源核对之后的实测基线**（findings `icon-a11y×18` · `icon-source×5`）：图标类
**2 条** —— 缺无障碍名 1 条（聚合）· **图标来源不符 1 条**（`i-arrow-right` / `i-arrow-left` /
`i-star` 是**手写的 path**，那份产物比图标体系早一天）· 描边那条这次不出（phosphor 是填充型，
按 `form` 分流跳过）。⚠ **第 3 条不是误报是真发现**：它正是"每做一页就重新发明一套 path"那件事。
另一份真实产物 `mobile-app-prototype/app.html`（17 个 symbol）**17/17 归属到 phosphor、零告警**；
把图标档改成别的系统 ⇒ **17 条全报出来**（能区分两种实现的实验）。

## 3. 明确不做（不是遗漏，是取舍）

- **图形语义 / 视角 / 细节是否与设计图同一套** —— 拿页面里的图去比**设计图**是另一个量级的工程且必然误报。
  它由 `library` + `sbot design icon` 在**生成时**保证，不由检查保证。
  ⚠ **与此不同的是「是不是从当前这套系统来的」**：那个有确定答案（拿几何跟库里的真文件比），
  已经做了 —— 见下面「图标来源核对」。两件事别混为一谈：前者问"像不像设计稿"，后者问"打哪儿来"。
- **图标与插画 / 商品图 / 品牌 Logo 的分类** —— v1 用**渲染尺寸 ≤32px** 当闸门代替分类。
- **尺寸「不在档内即报」** —— ⚠ Apple HIG 明确要求按视觉重量微调单个图标尺寸
  （"you may need to adjust its dimensions"），逐值报会把它推荐的做法报成错。只在**种类数失控**时提示一句。
- **多库映射表、光学尺寸挑变体、duotone 次色** —— 与上游 design.md 规范 issue #41 的 deferred 清单一致。
- **小程序 base64 / mask-image 的写法** —— 合法写法太多，逐个判必然假警报；写进清单教学，不做机器检查。

## 3b. 已知的误报口子（如实记，别当 bug 报）

- **描边判据扫的是整份产物，不只是图标**：页面里若有 SVG 图表（折线、饼图），它们的 `stroke-width`
  会被当成图标描边报出来。选择接受：判据靠"选择器像不像图标"必然更脆，而报告已写死"不等于做错了"。
  真的被烦到再收窄，收窄前先有实例。
- **`<img>` 只认双引号的 `width="20"` 与内联 `width:20px`**：单引号、tailwind 的 `w-5` 认不出 ⇒
  **漏报**而非误报。宁可漏。
- **尺寸未知的 `<img>` 一律不看**：没有尺寸就没法判断它是图标还是插画，猜一个必然错一半。
- **CSS 里的 `content: "★"` 不查**：那也是拿字形当图标，但它多半是装饰（真实产物里那个 ★ 就在
  一个奖杯徽记的伪元素里），报它属于按字符判的回潮。**漏报方向，安全。**
- **emoji 判定只看「元素自己的那段文本」**：`<button>开始 🎉</button>` 不报，`<button>🎉</button>` 报。
  用 JS 拼出来的 emoji 认不出 ⇒ **漏报**。
  ⚠ **必须走标签栈，不能用配对元素正则**（`<el>(.*?)</el>` 会把外层整段吞掉，于是**嵌套的可点按钮
  全部漏掉** —— 而现实页面里按钮几乎总是嵌套的；已配用例钉死）。
  **点名的**是可点元素里单独当图标用的 emoji（关闭按钮的 `✕`、分享按钮的 `📤`）；**不点名的**是装饰徽记和
  文案里的 emoji（`🎉 完成啦` 这类提示语）。按字符判会把文案里的 emoji 全报出来，噪音大到没法用。

## 4. 接口（两份档合起来才是契约）

⚠ 下面这份 `icons` schema 是**风格档**那一半（怎么画它）；`library` / `fallbackLibrary` /
`semantics` / `assets` 现在归**项目的图标档** `design/icons.md`（见下一节），风格档里的旧写法
只在**没有图标档时**仍然认。

front matter **顶层独立段**。⚠ **绝不进 `colors`** —— `styleRoles` 只扫 colors 的直接子键，
塞进去的颜色会参与角色兜底，彩度高的当场抢走 accent（gradient/elevation/status 当初独立成段就是这个原因）。

```yaml
icons:
  # ⚠ library / fallbackLibrary / semantics 中的前两个已迁到项目的 design/icons.md（见下一节）——
  #   有图标档时风格档里的这两行**一个字都不起作用**；下面留着只为说明「没有图标档时仍然认」。
  #   semantics 仍住风格档且优先级最高（项目自己的业务叫法：rank / fans / boost…）。
  style: "outlined"            # 线性 / 实心（在所选系统支持的范围内）
  weight: "regular"            # 字重档：只有声明了 weights 的系统认它（如 phosphor 的 thin/light/bold/duotone）
  grid: 24px
  strokeWidth: 2               # ⚠ 填充型库（phosphor / pixelart）没有描边，这三项对它无效
  linecap: "round"
  linejoin: "round"
  color: "{colors.ink}"        # ⚠ 引用而非 hex —— 写 hex 会悄悄放宽色板判据
  size:                        # ⚠ 必须缩进成子键:front matter 解析器只吃「按缩进建树」
    sm: 16px                   #    这一种,写成 { sm: 16px } 会被当成一个字符串整吞
    md: 18px
    lg: 24px
  semantics:                   # 只固化高频十几个,不求全
    back: "chevron-left"
    more: "more-horizontal"
```

`library / style / strokeWidth / grid / size / color` 六键**照搬**上游 design.md 规范 issue #41；
`fallbackLibrary / linecap / linejoin / semantics` 是**自有扩展**，理由分别是：双库可混（见下）、
描边端点是 HIG 唯一无条件项的组成、语义前移到生成时。

### 图标系统 —— 与设计风格**平级**的实体

**图标系统 = 图形从哪来 + 叫什么名 + 怎么起名；设计风格 = 怎么画它。**
两者**平级、各选各的** —— 换一套风格不该把图标一起换掉（`system` 若写在
风格档里，就等于把图标绑在风格上）。图标系统是**代码里的一张表**，不开放用户自定义
⇒ 没有用户目录、表单、落盘裁决。

**落点 = 项目里一份独立档 `design/icons.md`**，与 `design/styles/*.md` 平级：

```yaml
---
system: "tabler"                      # 用哪套(图形从哪来 + 整套叫法)
assets: "miniprogram/images/icons"    # 图标文件在哪(资产体检的扫描范围;多个目录用逗号分隔)
fallback: "none"                      # 取不到时不去兜底库(none/off/no/false 都收;默认会兜)
---
```

⚠ **为什么不是群配置**：`sbot design icon` 是 agent 在**项目目录**里跑的，它够不着群配置、也不知道
自己属于哪个群 ⇒ 取图标那条主路当场断掉；项目 clone 到别处也会把这个选择丢掉。
控制台群卡是**入口**，项目档是**落点**（与 `design use` 同款做法）。

| 系统 | 主库 | 形态 | 支持 | 兜底 |
|---|---|---|---|---|
| `lucide` | Lucide 2025 | 描边型 24 网格 | 线性 | tabler |
| `tabler` | Tabler 5130 | 描边型 24 网格 | 线性 · 实心 | lucide |
| `phosphor` | Phosphor 1512 | **填充型 256 网格** | 线性 · 实心 · **5 档字重(含双色)** | 无 |
| `pixelart` | Pixelarticons 1036 | **填充型 · 像素点阵** | 线性 | 无 |

⚠ **描边型 vs 填充型是比「网格/描边粗细」更硬的分野**：填充型库的轮廓已经转成填充路径，
`strokeWidth` / `linecap` / `linejoin` 对它**完全无效** ⇒ `checkIcons` 按 `form` 分流，
否则用这类系统的项目每份产物都会收到一串假的「描边不合规」。

⚠ **兜底只在参数同构的两套之间成立**（同 form + 同网格，已配用例钉死）。phosphor / pixelart
没有同构搭档 ⇒ **不配兜底**：一个像素风页面里冒出一枚矢量线性图，比缺一张图难看得多。

⚠ **字重归风格档**（`icons.weight`）——它与 `strokeWidth` 是同一件事在两种库上的表达：
描边型调 stroke-width，填充型换字重目录。⚠ phosphor 的六档是**六套独立几何**，
且 regular 档文件名无后缀、其余带 `-{字重}` 后缀（`gear.svg` / `gear-bold.svg`），
所以库定义里每个目录都显式声明 `suffix`。

⚠ **pixelart 不声明支持实心**：全库 1036 个文件里带 `-solid` 的只有 **53 个**（去掉 `-solid`/`-sharp` 两类变体后的基本名共 651 个 ⇒ 覆盖率 53/651），声明支持实心就是句假话。
它的词表也**如实缺三条**（`medal` 库里没有；`success`/`error` 只有裸的对勾与叉、没有圆圈态）——
硬塞一个形近的图标就成了「做了 A 让人以为做了 B」。

**两份档怎么合并**：

| 谁答 | 管什么 | 写在哪 |
|---|---|---|
| 图标档 | `library` / `fallbackLibrary` / `semantics` 词表 / `assets` | `design/icons.md` |
| 风格档 | `style`（线性/实心）/ `strokeWidth` / `linecap` / `linejoin` / `size` / `color` | `design/styles/*.md` 的 `icons` 段 |

理由是实测：16 份内置风格档里 **8 份声明的正是 style/strokeWidth/linecap/corner 这四项**（跨
1/1.25/1.5/2/3 五档）—— 把它们搬走等于让那 8 份声明当场作废；而「同一套 Tabler 图标，手绘风格里
1.5px、瑞士风格里 2px」本来就是对的。

**为什么系统必须同时带走「命名词汇」**（三条实测）：

| # | 结论 | 数据 |
|---|---|---|
| F1 | 系统封装的是**整个名字空间**，不只是词表 | lucide 2025 名 / tabler 5130 名，**同名只有 640**（占 lucide 32%、tabler 12%） |
| F2 | 换主库有真实视觉意义 ⇒ 两套站得住 | 8 个常用同名图标（search/heart/user/settings/calendar/clock/filter/plus）几何 **8/8 全不同** |
| F3 | ⚠⚠ **兜底会稀释主视觉，能把「选主库」整个架空** | 主库设 tabler 而仍用 lucide 词汇 ⇒ 只有 32% 命中 tabler，**其余 68% 走兜底、拿到 lucide 的画法** |

⇒ 只让项目「选一个库」**不够**。`semantics` 词表因此归系统：同一个「更多」，lucide 叫
`more-horizontal`、tabler 叫 `dots`；`delete` 一边是 `trash-2` 一边是 `trash`。词表 62 条
**逐条对着真实库文件核过**（两库同名 43 条，各自不同的 19 条）——
词表里写一个库里没有的名字，症状是「按语义名取图标却说两个库里都没有」。

**兼容**：没有图标档时，风格档 `icons` 段里的 `library` / `fallbackLibrary` / `assets` **仍然认**
（已经这么配着的项目不能当场失去图标来源）；两处都有时以图标档为准，并由 `iconSourceConflict`
出声点名「那几行现在不起作用了」——「两个消费者读不同来源」不出声，就会有一个长期正确、
掩护另一个长期失效。

**声明了系统给不了的 style** ⇒ `iconSystemGap` 出声（只报告不阻断）：那些图标不会来自你选的那套 ——
名字在兜底库里有同款就取那张，没有就退回另一种画法，**等于没选这套系统**。
⚠ 措辞按真实结果写，不写成「全部从兜底库取」：实测词表 62 条里 tabler 的实心只覆盖 **48 条**，
剩下 14 条必然退回线性 ⇒ **混着出是常态**。取图标那行摘要因此**按手里这几张图真实的
`fill` 报**（`iconIsFilled` 一处判据），不照着声明写「实心」。

**入口**：CLI `sbot design icons`（看有哪几套 · 本项目在用哪套）/ `sbot design icons use <系统>`；
控制台「模型 · 库」页的**图标库**一节（与设计风格库并列，每套配 8 个真实渲染的样张）+
「群 · 项目」页每个群卡的**图标**行（选了就写进那个项目的 `design/icons.md`）。
⚠ 换系统会换掉整套命名词汇，而**页面上已经取过的图标不会自动跟着变** ⇒ CLI 要 `--force`、
控制台要确认一次。

### 两套口径都收，单数 `icon:` 也认

写档的是人，不该逼他记 SVG 属性名 ⇒ **同一件事的两种说法都收，归一到 SVG 那套**（归一只在
`iconSpec` 一处，别再各写一份）：

| 写档常见写法 | 归一成 | 说明 |
|---|---|---|
| `style: line` / `linear` / `outline` | `outlined` | |
| `style: solid` / `fill` | `filled` | |
| `corner: sharp` / `round` | `linejoin: miter` / `round` | 显式 `linejoin` 优先于 `corner` |
| `strokeWidth: "1.5px"` | `1.5` | `parseFloat` 早就吃掉了，不需要额外翻译 |

**单数 `icon:` 段等同于 `icons:`**（两个都写时 `icons` 赢）。内置风格档里写的多是单数 `icon:`,
不认它的话症状是「明明声明了却报未启用」。回落放在**读取层**而不是改那些文件：`design use` 是逐字节
复制预设进项目的，改资产救不了已经复制出去的档；而 `withKeptSections` 会把这类段原样带过控制台
往返，不会自己烂掉。它只声明 `style / strokeWidth / linecap / corner` 四项 —— **恰好就是验收要用
的那四项**，一项不多一项不少 ⇒ 回落即得全部验收能力，不用替作者编任何东西。

### 图标来源核对 —— `design check` 的第四条判据

前三类查的是「画得对不对」（描边 / 端点 / 无障碍名 / 位图），这一条查**这张图是不是从当前这套
图标系统来的**。

⭐ **要抓的情形**：图标档写着 `system: pixelart`，而页面里的 `home` 与 **Tabler** 的
path 逐字一致 —— 先按 Tabler 取过一份 sprite，换了系统没重取。描边 / 端点 / 无障碍名这几条检查都不会报,
因为**它们不查「打哪儿来」**;「换系统后已取过的图标不会自动跟着变」光靠提醒没人管。
⚠ 更糟的一层：选了**填充型**系统时，`checkIcons` 会按 `form` 跳过描边三项，而那恰恰是唯一能
看出「页面里混着描边型图标」的判据 ⇒ **选了填充型系统，反而查不出来源错**。

**四条判据，全是确定性事实**：

| # | 判据 | 要不要装库 |
|---|---|---|
| ① | 来源标记 `data-icon="库/名字"` 写着**当前系统与兜底库之外**的库 | 不要 |
| ② | 名字在当前系统里有，但**图形与库里那张不一致** | 要 |
| ③ | 名字在当前系统里没有，而图形与**另一套库**的同名图标**逐字相同** | 要 |
| ④ | 当前系统是填充型，页面里却有描边型图标（填充型库的图形里根本没有 stroke） | 不要 |

**来源标记是产出时留下的**：`sbot design icon` 给每个图标加 `data-icon="tabler/home"`，`--sprite`
加在每个 `<symbol>` 上。⭐ **检查器只能发现不一致，"能发现"这件事本身要靠产出时留下的东西** ——
注释形式的署名 agent 会顺手删掉（产物里常常一条 `<!--` 都不剩），属性跟着图形走，删它得动
每一个 symbol。

⚠ **名字从哪儿来**：sprite 的 `<symbol id="…">`。**整个 id 都要收，不能只认自家的 `i-` 前缀** ——
agent 产出的 symbol 常用 `id="p-house"` 这种自己起的前缀，只认自家格式的话一个都认不出，
而输出会是「没有认得出来源的图标」，**看着与"查过没问题"一模一样**。
剥前缀（`^[a-z]{1,4}-`）得到的候选名**只当猜的**：`x-circle` 这类名字本身就以短段开头，剥掉会变成
另一个真实存在的图标 ⇒ 猜出来的名字只认「几何逐字相同」这种**正证据**，绝不用来说"图形不一致"。

三条**不报**的纪律（都配了用例）：

1. **名字在任何库里都没有 ⇒ 一个字不报** —— 徽章 / logo / 品牌图是正当的项目自有图形。
2. **③ 必须拿几何说话，不能只按名字** —— 当前系统的库没装时，「别家有这个名字」什么都证明不了。
3. **兜底库算自己人** —— 取不到时走兜底是设计好的正路，不是错。

**"没查"要说出口**（这一维的沉默有三种成因，报告上长得一模一样）：没选图标系统 /
这台机器没装当前系统的库（只剩 ①④，报「只核对了一半」）/ 文件里没有认得出来源的图标。

**几何比对怎么做的**：库文件先过一遍**同一个归一器**再比（页面里那份就是这么产出来的），
比之前把空白全去掉 —— 归一那步会吃掉 `d=` 里跨行的空白，严格比会把同一张图判成不同。
去空白理论上会撞车，但那只造成**漏报**，方向安全。

### 图标库署名

我们出的 sprite 一定带 `<!-- icons: Tabler — MIT -->`（Lucide 是 ISC，其余三套 MIT，**都要求
副本保留声明**）。agent 改写产物时常把注释删光,所以要查。

⇒ `design check` 报一条 `icon-license`，但**只对 sprite 形态**：那行注释是随 sprite 一起出的，
「本来有、现在没了」才判得了；单图标形态从来没带过署名（提醒走 stderr）⇒ 拿它要求署名就是
凭空指控。**整轮只出一行**，且措辞给正当例外留出口（「声明放在别处也算，那就不用管这条」）——
一条站不住的指控会让整份报告被丢掉。

### 图标资产体检 `sbot design icon-assets`

`design check` 查的是**页面写法**；这条查**图标文件本身**。分成两条命令而不是合并，是因为节奏不同：
页面检查每次交付前跑，资产体检整理时才跑 —— 混进交付报告里，那几十行会把真正要看的东西淹掉。

扫描范围**必须声明，绝不自动发现**：

```yaml
icons:
  assets: "miniprogram/images/icons"     # 多个目录用逗号分隔（front matter 解析器不吃数组续行）
```

⚠ 不自动发现的理由是实测出来的：真实项目里同一棵目录树混着 `flame/`（200×200 插画）、
`badges/`（徽章，天然多色）、`dist/`（构建产物副本）—— 全扫进来的报告是废的。

报**三件确定性事实**，一件都不需要视觉判断：

| 报什么 | 为什么是它 |
|---|---|
| 没用 `currentColor`（写死颜色） | ⭐ **链的第一环**：颜色写死 ⇒ 换色只能另存一份 ⇒ 副本爆炸 ⇒ 没有单一来源 ⇒ 改一个要找齐所有副本 ⇒ 实际没人改 ⇒ 漂移固化 |
| 图形完全相同的多份 | 链的后果。几何指纹只留 `d=` 与基本形状的几何属性，**表现属性全丢** ⇒ 同图不同色必然撞成一组 |
| 描边 / 端点 / 连接 / 网格偏离声明 | 与 `design check` 同一套判据，只是对象换成文件 |

**某项目实测基线**（119 个 svg）：写死颜色 118/119 · 色值 40 种 · 图形完全相同 30 组共 77 个文件
（合并可省 47 个）· 描边 3 种偏离 · 网格 6 种偏离。`icons/colored/*` 与 `icons/*` **逐字同几何、
只有写死的颜色不同** —— 链在文件清单里就是实物。
⚠ **几何反而是整齐的**（本来同源，lucide 导出）⇒ 打散一致性的是**导出之后的加工**。

三条措辞纪律（都配了用例）：

1. **只说事实不下判断** —— 报「几何相同」不报「冗余」：小程序 tabbar 的选中/未选中只能是两个
   图片文件、改不了色，同图两色是**平台强制**的。把事实说成缺陷，人发现一条不成立就会连整份报告一起丢掉。
2. **截断必须出声** —— 组数超上限时明说「还有 N 组未列出」，否则「只列了 8 组」会被读成「只有 8 组」。
3. **只出清单不自动改** —— 删图标文件不可逆，且「哪个名字该留」是语义判断。

退出码：`0` 干净 / `3` 有发现 / `1` 命令失败。

### ⚠ 没声明 `library` 时按 `style` 定库

**这不是偏好是事实**：lucide 里**实心图标数为 0**（`ICON_LIBS.lucide` 只有一个线性目录），一份
`style: filled` 的档挂在 lucide 上不可能工作。恒定默认 lucide 会让它**静默拿到线性图标**，而
「声明实心却拿到线性」在页面上一眼可见。⇒ 没写 `library` 时：`filled` ⇒ tabler，其余 ⇒ lucide。
显式声明永远优先；显式声明了却取不到实心时，`iconStyleGap` 出声（**只报告不阻断**），
同时 stderr 那行摘要按**真拿到的**报，不再跟着声明写「实心」——否则两处一起骗人。

**取图标的三条硬规矩**（都在 `readIcon` / `normalizeIconSvg` 里，各配一条用例）：
1. **名字过白名单** `^[a-z0-9][a-z0-9-]*$`，语义表里映射出来的也要过 —— 名字要拼进文件路径，
   `../` 一律拒（凡 agent 够得着的入口输入一律不可信）。
2. **实心图标不按线性那套改写** —— Tabler 的 `filled/` 那批是 `fill="currentColor"` 且没有描边，
   硬套 `fill:none` + `stroke-width` 会把实心图形描成一圈轮廓。判据取**源文件的 fill**，不取声明的 style。
3. **查找顺序先按 style 再按库** —— ⚠ 实测两个库里**没有一个名字是 filled 独有的**
   （1054 个 filled 名字 outline 里全都有）⇒ 只按库排的话 `style: "filled"` 永远拿不到实心，
   声明就成了空话。库之间参数同构、换库看不出来；线性换实心是另一个东西，所以 style 的约束更强。

**为什么允许双库**：Lucide 与 Tabler 的分发文件属性逐字相同 ——
`viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round"`。
参数同构 ⇒ 混用不破坏 Apple HIG 那条唯一的无条件要求（"use the same stroke weight in every icon"）。
所以检查器按**参数**判，不按库名判。Phosphor（六字重）、Heroicons（292 个、solid 实心）不满足同构，不进兜底位。

## 5. 代价与回滚

- **四个包合计约 160MB**（本机 du：lucide-static 61M · @tabler/icons 49M · @phosphor-icons/core 37M · pixelarticons 15M）
  ⇒ **不随 sbot 分发**（tarball 才 640KB），机器上单独装，与 rembg 同款做法。
- **没装 = 软降级**：`sbot design icon` 报"取不到"，agent 退回自创 path，`doctor` 如实标一行。
  ⚠ **不阻断**（配置类策略对半可信 agent 本质不可强制）。
- **许可**：Lucide = ISC（要求副本保留版权声明 ⇒ 内联/sprite 输出保留一条注释）；Tabler = MIT。
  ⚠ **SF Symbols 一个都不能用** —— 许可只覆盖 Apple 平台上运行的软件界面，网页与跨平台一律禁止。
  Apple HIG 可以引作规范依据，但它推荐的那套符号我们用不了。
- **回滚**：`icons` 段是纯增量，删掉即回到没有图标体系时的行为（检查器整类跳过、清单不提图标）。

## 6. 外部依据

- Apple HIG · Icons：consistent "size, level of detail, stroke thickness (or weight), and perspective"；
  "use the same stroke weight in every icon"（**唯一无条件句**）；"use a vector format like PDF or SVG"；
  "Provide alternative text labels"。⚠ **全篇无数字**，也**全篇没提 emoji** —— 禁 emoji 当操作图标是我们
  自己的规则（理由：不可着色、跨平台字形不一、VoiceOver 读的是 emoji 名而不是动作），不要挂在 Apple 名下。
- 上游 design.md 规范 issue #41「add Iconography section and `icons.*` tokens」——六键来源。
- Lucide(实装 1.31.0 = 2025 个)/ ISC / 24 网格 · stroke 2 · round；Tabler 6184（outline 5130 + filled 1054）/ MIT / 24 网格 · 2px。
